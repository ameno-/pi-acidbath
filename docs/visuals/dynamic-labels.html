Dynamic Status Language — V1 Deterministic / V2 Adaptive

The orb state machine already exists in index.ts. V1 is a pure label synthesizer wired through apply(); V2 adds an optional, gated intent provider. No thinking-block parsing.

2. V1 — pure deterministic label synthesis

flowchart LR E["agent event\nevent name + toolName"] --> S R["render-time args\n(renderCall/renderResult)\nfile_path / command / pattern\nisError / isPartial"] --> S S["synthesizeLabel(input)\nPURE — O(1), no I/O, no timers"]:::win --> O["{ orbState, message }"] O --> APPLY["apply(ctx)\nchurn guard: only setWorkingMessage\nif string changed"] APPLY --> DEBOUNCE["100ms trailing debounce\n≤1 label / 100ms window"] DEBOUNCE --> RENDER["bounded label timer\nthen existing requestRender"] classDef win fill:#0a1510,stroke:#39ff14,color:#39ff14
What is deterministic from event payloads (confirmed):
  • event name → orb state (already wired)
  • event.toolName on tool_call → "Running {tool}…"
  • renderCall args (file_path, command, pattern) → scoped labels like "Editing src/index.ts"
  • isError / isPartial (render context) → "{tool} failed" / "Command finished"
What is NOT deterministic (out of V1 scope):
  • tool_result.content text — free-form, tool-specific, unverified shape → do not parse
  • thinking-block content — hideThinkingBlock:true; only a placeholder label is set
