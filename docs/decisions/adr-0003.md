# ADR-0003: Agent core is registry, runner, and envelope only

## Status
Accepted

*Tracked in Beads:* [acidbath-9ih.3](bd-acidbath-9ih.3)
*Linear:* [MIGHT-499](https://linear.app/acids/issue/MIGHT-499/acidbath-harness-core-agent-and-subagent-substrate)
*Date:* 2026-09-23
*Author:* Ameno

## Context
The user asked for OMP's agent/sub-agent *core*, not its delegation heuristics, workflows, or automatic fan-out. Pi already ships `createAgentSession` and a reference `subagent` example with chain/parallel modes.

## Decision
Implement profiles, discovery, bounded isolated `createAgentSession` runs, cancellation, a concurrency ceiling, streaming updates, and a structured `ResultEnvelope`. Expose an explicit `subagent` tool plus `/agents list|run`. Default max concurrency is 4. Nested child fan-out is off unless a profile sets it. Project-local profiles require TUI confirmation. Do not port OMP Task-tool policy, workflowz, or auto-orchestration.

## Alternatives Considered
- Slash-command-only runner with no tool: rejected; the requested substrate must be invocable by the model.
- Copy Pi's chain/parallel example wholesale: rejected; parallel is allowed only when explicitly requested, and chain/workflow policy stays out.

## Consequences
* Testable core without a TTY for registry/envelope logic.
* Workers still need the Pi SDK at the execution boundary.
* No silent fleet spawning.

## Amendment — run-outcome fidelity (2026-09-28)

Live execution testing surfaced two failure-reporting defects that the pure
module tests could not catch, because both lived at the Pi execution boundary.

**1. Provider failures were reported as successful empty runs.** When a model
call fails, Pi does not throw out of `session.prompt()`. The failure lands as
an assistant message with `stopReason: "error"`, empty `content`, and the cause
in `errorMessage`. The runner only looked for text parts, so it produced a
success envelope with no output — which the UI then rendered through its error
branch as a bare `(no error message)`. Two independent bugs: the failure was
misclassified, and `formatEnvelope` conflated "empty success" with "failure".

*Decision:* extract the run result through a pure `extractRunResult` that
promotes `stopReason === "error"` or a non-empty `errorMessage` to a real
error envelope. `formatEnvelope` now branches on `ok` alone and renders empty
success as `(no output)`. The envelope's stable `error.code` is printed in the
UI, since prose alone cannot distinguish a timeout from a cancellation from a
missing role.

**2. A malformed user registry was swallowed.** A `roles.json` that failed to
parse reverted to built-in defaults with no message, so user edits appeared to
be ignored.

*Decision:* retain the parse failure and surface it the next time `/role list`
renders, alongside the path and reason.

Supporting changes: the fan-out ceiling is now a hard 8 items enforced by the
tool schema as well as the runner; the caller's `AbortSignal` is threaded into
every sub-session so tool cancellation and timeout abort real work; and
redaction was widened to AWS, GitHub, Google, Slack, bearer, and
assignment-shaped credentials while preserving ordinary prose such as
`task-item`.

Preflight, clamping, result extraction, error description, and redaction are
pure functions in `agents.ts`, covered by `scripts/test-harness-agents.mjs`.
