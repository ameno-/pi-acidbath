# ADR-0004: Exact-prose magic words via input transform

## Status
Accepted

*Tracked in Beads:* [acidbath-9ih.4](bd-acidbath-9ih.4)
*Linear:* [MIGHT-498](https://linear.app/acids/issue/MIGHT-498/acidbath-harness-exact-prose-magic-words)
*Date:* 2026-09-23
*Author:* Ameno

## Context
OMP matches enabled keywords as standalone lowercase prose and injects hidden notices. Regex matching produces false positives in code, paths, and identifiers. Magic words must never run commands or tools.

## Decision
Single registry table (`config/magic.example.json` + `extensions/harness/magic.ts`). Match exact lowercase standalone tokens. Ignore fenced code, inline code, HTML/XML, identifiers, paths, and file extensions. Use Pi `input` transform / hidden notice injection; do not mutate the user-visible prompt. Optional thinking-level raise only when a keyword declares it. Global and per-keyword enable switches default to off until configured.

## Alternatives Considered
- Per-keyword regex files: rejected; OMP centralized this for a reason.
- Auto-running `/handoff` or `/recap` from a match: rejected; notices are hints only.

## Consequences
* Low false-positive rate.
* Users must enable keywords explicitly.
* No command execution from prose.

## Amendment — fence masking and turn-scoped state (2026-09-28)

Probing the matcher against real inputs found two fence defects that the
existing tests missed, because the fixtures only covered well-formed pairs.

**Fence masking.** The mask used a `` ```...``` `` regex, which failed two
ways: an *unterminated* fence matched nothing, so keywords inside code
leaked through as prose; and `~~~` fences were not recognized at all. Both
are common in real input — the first whenever a user is mid-edit, the
second because tilde fences are equally valid Markdown. Fences are now
parsed as line-oriented pairs: a closer must use the same character and be
at least as long as its opener, and an unclosed fence masks to the end of
the prompt.

**Turn-scoped state.** `pendingMatches` was set in `input` and consumed in
`before_agent_start`. A turn aborted in between (Esc during submit) left
the matches in place, so the next turn injected hints belonging to a prompt
the user never sent. Both `input` and `agent_settled` now reset the pending
list, so matches cannot outlive their turn.

**Disable semantics.** Disabling the last enabled keyword left
`registry.enabled` true, so `/magic list` reported matching as "on" while
nothing could match. Disabling now clears the flag; enabling still sets it.
