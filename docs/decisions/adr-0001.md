# ADR-0001: Separate non-visual harness extension

## Status
Accepted

*Tracked in Beads:* [acidbath-9ih](bd-acidbath-9ih)
*Linear:* [MIGHT-493](https://linear.app/acids/issue/MIGHT-493/acidbath-integrate-omp-inspired-harness-capabilities)
*Date:* 2026-09-23
*Author:* Ameno

## Context
Acidbath owns Pi presentation (header, footer, editor, activity rail, built-in tool renderers). The existing `compactor` extension owns bash-result compaction. OMP-inspired capabilities (handoff, roles, agent core, magic words, recap, Codex compaction) are session/runtime features, not UI. Mixing them into `extensions/acidbath/index.ts` would collide with staged UI work and the documented ownership boundary.

## Decision
Ship a separate non-visual Pi extension at `extensions/harness/` registered in `package.json` `pi.extensions`. Acidbath remains UI-only. The bash-result compactor remains independent. Harness commands, tools, and compaction hooks must not call `setHeader`, `setFooter`, `setEditorComponent`, or wrap built-in tools.

## Alternatives Considered
- Fold capabilities into Acidbath: rejected; collides with UI ownership and staged renderer work.
- Vendor OMP runtime: rejected; Pi already supplies session, model, compaction, and SDK primitives.

## Consequences
* Independent tests and load order.
* Extra extension surface to document.
* Harness can be disabled without losing Acidbath UI.
