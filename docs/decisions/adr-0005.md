# ADR-0005: Handoff creates a child session; recap stays in-session

## Status
Accepted

*Tracked in Beads:* [acidbath-9ih.1](bd-acidbath-9ih.1), [acidbath-9ih.5](bd-acidbath-9ih.5)
*Linear:* [MIGHT-497](https://linear.app/acids/issue/MIGHT-497/acidbath-harness-structured-cross-session-handoff), [MIGHT-494](https://linear.app/acids/issue/MIGHT-494/acidbath-harness-persistent-session-recap)
*Date:* 2026-09-23
*Author:* Ameno

## Context
OMP `/handoff` currently compact-in-place. Native Pi's example `/handoff` creates a new session with an editable generated prompt. OMP has no built-in recap command. These are different mental models.

## Decision
`/handoff [goal]` generates a bounded structured document, lets the user edit it, then `newSession({ parentSession, withSession })` prefills the replacement editor and never auto-submits. `/recap [focus]` appends a custom session entry (not LLM context by default) with a renderer. Recap does not write notes outside the session.

## Alternatives Considered
- OMP in-place compaction handoff: rejected; Pi already has compaction, and the user asked for transfer.
- Recap as `~/.pi/agent/notes/*.md`: rejected; session-persistent custom entries survive resume/branch without a second store.

## Consequences
* Clear command split.
* Handoff depends on replacement-session context, not stale `ctx`.
* Recap is inspectable history, not a prompt injection.

## Amendment — injection boundary and visible truncation (2026-09-28)

Two defects found by probing the pure functions against hostile and
oversized inputs.

**Injection boundary.** The recap prompt interleaved untrusted text
(the conversation transcript) directly beneath its own structural
delimiters. A transcript line reading `Conversation so far:` or a bare
`---` therefore read as part of the prompt's framing rather than as data,
letting conversation content pose as instructions to the summariser. The
callers' `focus` argument had the same exposure.

Untrusted lines that imitate a structural delimiter are now prefixed with a
zero-width joiner, which changes the line's identity without altering what
it means. The transcript is additionally fenced between explicit
`BEGIN`/`END` markers, labelled as data-not-instructions, and the framing
sentence is restated after it so the tail of the prompt is unambiguous.

**Truncation visibility.** `serializeRecapSource` dropped whole leading
blocks to fit the budget and returned the surviving tail with no
indication that anything was removed. A recap built from a truncated tail
would summarise it as though it were the whole session — the precise
failure a recap exists to prevent. Dropped entries are now announced with
`[…N earlier entries omitted…]`, and the marker counts against the budget,
so shedding one more block is reported honestly. `truncateBlockBody` also
respects very small budgets, which it previously overshot.

**Handoff.** The same injection class applied to the handoff prompt, whose
goal argument and conversation text are equally untrusted; the same fencing
and defusing is applied. Two further handoff defects surfaced:

- `serializeHandoffSource` stripped a trailing partial line and could then
  return the body *without* the truncation marker, so a truncated handoff
  read as a complete one. The marker is now guaranteed whenever content
  was dropped.
- A non-positive or very small `maxChars` returned the full 12-character
  marker, exceeding the caller's budget. The budget is now hard: the
  marker is clamped to whatever room exists.

`buildHandoffPrompt` also no longer throws on a missing goal (the Pi command
guards it, but a pure function that throws on an absent argument is a
landmine). Child-session creation in `/handoff` is wrapped, so a failure
there reports a reason instead of escaping the command handler.
