# ADR-0005: Handoff creates a child session; recap stays in-session

## Status
Accepted

*Tracked in Beads:* [acidbath-9ih.1](bd-acidbath-9ih.1), [acidbath-9ih.5](bd-acidbath-9ih.5)
*Linear:* [MIGHT-497](https://linear.app/acids/issue/MIGHT-497/acidbath-harness-structured-cross-session-handoff), [MIGHT-494](https://linear.app/acids/issue/MIGHT-494/acidbath-harness-persistent-session-recap)
*Date:* 2026-09-23
*Author:* Ameno

## Context
OMP `/handoff` currently compact-in-place. Native Pi's example `/handoff` creates a new session with an editable generated prompt. OMP has no built-in recap command. These are different mental models.

## Decision
`/handoff [goal]` generates a bounded structured document, lets the user edit it, then `newSession({ parentSession, withSession })` prefills the replacement editor and never auto-submits. `/recap [focus]` appends a custom session entry (not LLM context by default) with a renderer. Recap does not write notes outside the session.

## Alternatives Considered
- OMP in-place compaction handoff: rejected; Pi already has compaction, and the user asked for transfer.
- Recap as `~/.pi/agent/notes/*.md`: rejected; session-persistent custom entries survive resume/branch without a second store.

## Consequences
* Clear command split.
* Handoff depends on replacement-session context, not stale `ctx`.
* Recap is inspectable history, not a prompt injection.
