# ADR-0006: Codex compaction uses modelRegistry.complete with native fallback

## Status
Accepted

*Tracked in Beads:* [acidbath-9ih.6](bd-acidbath-9ih.6)
*Linear:* [MIGHT-495](https://linear.app/acids/issue/MIGHT-495/acidbath-harness-openai-compaction-for-codex-sessions)
*Date:* 2026-09-23
*Author:* Ameno

## Context
OMP implements provider-native Codex compaction (`compaction_trigger` V2, `/responses/compact` V1) with proprietary headers and WebSocket transport. Installed Pi exposes `session_before_compact` plus `ctx.modelRegistry.complete()`. Inventing a `compaction: "codex"` flag on `complete()` would not hit OpenAI's compact endpoint. Raw `fetch` to Codex would require assembling ChatGPT account/attestation headers and risks logging credentials.

## Decision
Gate on OpenAI Codex models and an opt-in setting (`PI_ACIDBATH_CODEX_COMPACT=1`, default off). The production path summarizes via a dedicated `compact` role using `modelRegistry.complete` on the prepared conversation, returning `{ compaction: { summary, firstKeptEntryId, tokensBefore, usage } }`. Any auth, abort, empty, or parse failure returns `undefined` so Pi's native compaction runs. Do not log tokens, headers, or bodies. Native `/responses/compact` is deferred until tests prove the installed provider auth/header contract.

## Alternatives Considered
- Copy OMP V2 streaming transport: rejected; Codex-specific attestation/WebSocket stack is out of scope and unsafe to reimplement casually.
- Raw fetch with `getApiKeyAndHeaders`: deferred; higher leak risk until a proven contract exists.

## Consequences
* Safe fallback always available.
* First version is LLM summarization with a cheaper/faster role, not true provider-native compact.
* Later work can add native compact behind the same gate without changing the extension event shape.
